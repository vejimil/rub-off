# Seated Tailor에서 배운 것 (10/26–10/31)

Rub-Off가 처음부터 다시 겪지 않도록 옮겨 적은 것. 원문과 실측 숫자는 `~/Desktop/seated-tailor/docs/EXPERIMENTS.md`, `ARCHITECTURE.md`, `FLAT-CONVENTIONS.md`. 아래 숫자는 모두 실제 실행 결과다.

## 1. Meta Model API 실측 교훈

### SAM 3.1
- **한 단어 명사 하나.** 리스트·명령·공간 표현("왼쪽 소매") 불가. 좌우는 코드에서 박스로 걸러라.
- **단어 선택이 결과를 바꾼다.** 잠옷 바지에 `trousers` 0프레임, `pants` 205/205프레임. `shoe`는 맨발을 못 잡고, `foot`은 잡는다. Rub-Off에서도 "shirt"/"t-shirt"/"top", "sleeve", "collar", "paper", "fabric"/"cloth"를 실제 사진으로 비교하고 시작할 것.
- **비슷한 물체를 섞어 잡는다.** A4를 `card`로, 카드를 `paper`로도 잡았다. 크기가 3배 다르니 그대로 쓰면 치명적. 보이는 가로세로 비율(A4 1.41, 카드 1.59)로 판정하고, 서로 절반 이상 겹치는 두 기준 물체는 하나로 본다.
- **같은 무늬 상하의는 마스크가 섞인다.** 바지 마스크에 같은 무늬 소매가 들어왔다. 옷을 펴놓고 찍는 Rub-Off에서는 **배경이 옷과 대비되는 단색**이어야 한다(촬영 안내에 넣기). 소매 마스크를 몸판에서 빼는 식의 교정도 가능.
- **합성 이미지로 테스트하면 안 된다.** ffmpeg로 그린 사각형은 "paper", "white rectangle", "square" 어느 것도 못 잡았고, 실제 사진은 잘 잡았다. 실제 사진으로만 시험.
- 마스크는 base85, 프레임보다 작은 래스터(H, W). `@meta-sam/parser`(ESM, Node ≥20.17, 0.0.13 이상)로 파싱하고 한 그리드로 리샘플. 스트림은 한 번만 소비 가능. Next 라우트는 Node 런타임.
- 0개 매치는 에러가 아니라 빈 출력. 프롬프트 `w`/`h`는 회전 반영 후 표시 크기. 프레임 밖 포인트는 400.
- **옷이 옆으로 누우면 못 찾는다.** 모자가 왼쪽으로 간 데님 후드에서 `hoodie`·`hood` 0개, 같은 사진을 목이 위로 오게 돌리면 0.64·0.94(11/3). SAM에 보내기 전에 사진을 바로 세운다(방향은 Spark가 고른다).
- 어떤 옷 단어도 못 찾을 때 `clothing`은 잡았다(0.94). 다만 바닥의 다른 옷도 잡으니 가장 큰 마스크 하나만 쓴다.
- 이미지 $2.50/1k. 사진 1장 × 5개 개념 = $0.0125.

### Muse Spark 1.3
- Responses API, 구조화 출력은 `text.format`(json_schema). `store: false`, 스트리밍(비스트리밍은 504 가능), `reasoning.effort: low`, `max_output_tokens` 충분히. 재귀 스키마 불가. `logprobs` 400.
- **Spark가 낸 숫자·시간은 믿지 않는다.** 시간은 전사에서, 프레임은 SAM 마스크에서, cm는 기하에서.
- **가리키게 하면 약하고, 고르게 하면 강하다.** 같은 프레임에서 "가리킨 곳의 좌표를 말해라"는 틀렸고, SAM 손 마스크를 빨갛게 칠해 "이 손이 닿은 부위를 목록에서 골라라"는 맞았다. 부위 설명 목록을 함께 주면 더 낫다. Rub-Off에서는 SAM 마스크를 색칠해 보여 주고 "이 조각은 몸판/소매/칼라/안단 중 무엇인가"를 고르게 하는 식으로 쓴다.
- **답이 실행마다 조금 다르다.** 열거형(enum)으로 답 범위를 좁히고, 결정은 코드가 한다.
- 0–1000 좌표는 **보낸 이미지 그대로**에 상대적이다. 리사이즈·크롭했으면 그 이미지 기준.
- 영상 입력은 MP4만. 오디오 이해는 공식적으로 저하됨 → Voice Transcribe 먼저. (Rub-Off는 사진만이라 해당 없음.)
- 도구 검색과 구조화 출력은 같이 못 쓴다.
- **옆으로 누운 옷은 종류를 헷갈린다.** 같은 데님 후드를 목이 위면 3/3 후드, 밑단이 위면 3/3 바지(소매를 다리로), 옆으로 누우면 반반(11/3). "보이는 부분 먼저 고르기", 설명 추가, `effort: medium`(답이 잘리기도 함) 모두 소용없었다. 종류를 알려 주고 "모자가 어느 쪽이냐"만 물으면 3/3. 그래서 종류를 사용자가 고르면 방향만 묻는다. 자동 판별은 기하로 검증한다: 그 옷의 기준점(목선, 가랑이)이 없으면 사진을 첫 답과 반대로 세워 다시 묻는다(같은 모델에게 "맞아?"라고 묻는 건 같은 착각을 되풀이할 뿐; Spark에게 받은 "두 번째 후보"도 "그 밖의 것"이라 쓸모없었다). 그래도 실패하면 무엇으로 봤는지 말해 사용자가 고르게 한다.
- `max_output_tokens`는 추론에도 쓰인다. 판별(1000)·배치 확인(2000)이 한도에 걸려 각각 3000·4000으로 올렸다.

### Muse Image 1.0
- 편집에 `mask` 없음(400). SAM 마스크 영역만 원본에 합성하라. `size`는 비율만 정하니 출력 크기를 맞춘 뒤 합성. 기본 WebP. 웹·이미지 검색 끄고 `reasoning_strength: low`.
- (Rub-Off 11/3) 여러 장 입력은 multipart 키 `image[0]`, `image[1]`. OpenAI SDK는 `image[]`로 보내 400이 나므로 직접 보낸다. 옷 사진 + 원단 사진 두 장으로 "이 원단으로 만든 옷"이 윤곽·주변을 지킨 채 나옴. "재질만 바꿔라"보다 "모든 부분을 이 원단으로, 원래 프린트는 지워라"가 잘 됨.

### Voice Transcribe, Files
- `ENDPOINTING` 모드가 아니면 턴이 안 온다. 타임스탬프는 턴 단위. (Rub-Off 미사용.)
- 업로드는 `expires_after` 없으면 영구. Inline 50 MB, Files 1 GiB.

## 2. 측정 교훈 (Rub-Off의 핵심이라 가장 중요)

- **가장자리에 걸린 기준 물체는 쓰지 않는다.** 잘린 A4도 사각형으로 보여서 실제보다 작은 A4로 계산되어 cm가 커진다. 한 손 촬영 25프레임 중 네 모서리가 다 보인 건 1개. → 촬영 안내: **A4 네 모서리가 모두 화면 안에**. 걸리면 측정 거부.
- **카드 모서리는 둥글다.** 꼭짓점을 그대로 쓰면 2–3% 작게 나온다. 각 변의 가운데에 직선을 맞추고 교차점을 꼭짓점으로 쓰면 0.7% 오차. A4도 같은 방법으로.
- **가려진 꼭짓점을 걸러라.** 손가락이 모서리를 덮으면 비율이 1.24–1.34로 뒤틀린다(카드 1.59). 마스크 면적 / 사각형 면적 비율 허용 범위 ±6%.
- **원근 보정(호모그래피)은 조건부로.** 네 모서리가 깨끗할 때만, 기준 물체 대각선의 1.5배 거리까지만. 그 밖은 둘레 기반 단순 px/cm에 오차 가산(대각선 거리마다 +2%). 틀어진 꼭짓점으로 만든 호모그래피를 외삽했더니 44–127 cm, 한 프레임은 부호가 뒤집혔다. Rub-Off는 A4가 옷과 같은 평면이고 카메라를 수직으로 두므로 조건이 훨씬 좋지만, 같은 가드를 그대로 둔다.
- **물리적으로 가능한 범위를 측정값마다 둔다.** 벗어나면 숫자를 보이지 않는다. (셔츠 총장 40–100 cm, 가슴단면 35–80 cm 같은 식.)
- **신뢰도는 마스크 품질만 보면 안 된다.** 틀린 70.5 cm에 "높음"이 붙은 적이 있다. 기하 조건(모서리 가림, 외삽 거리, 기울기)이 신뢰도에 들어가야 한다.
- **±에 안 잡히는 계통 오차가 있다.** 앞에서 찍은 발은 발가락이 카메라에 가까워 항상 아래로 찍혔다(+14%, 제시한 ± 밖). 측정하기로 한 값마다 "이 각도에서 원리상 잴 수 있는가"를 먼저 묻는다. 옷을 펴놓고 수직으로 찍으면 두께(옷의 부피) 때문에 윤곽이 조금 커질 수 있다 → 실제 옷 줄자와 비교해 보정값을 정한다.
- **정답과 비교하기 전까지는 모른다.** 테스트 데이터로는 안 드러났고, 손으로 잰 값과 비교해서야 알았다. Rub-Off는 첫 촬영부터 **옷 줄자 치수를 함께 기록**한다(총장, 가슴단면, 어깨, 소매, 밑단).
- **사람이 더 쉽게 재는 값이 있다.** 카메라가 못 보는 값은 묻는 게 낫다("카드 몇 장 높이?"). Rub-Off에서는 소매 둘레·목둘레 같은 입체 값은 사용자가 재서 넣는 칸을 둔다.
- 정확도 기대치(핀홀 기하, 가정): 기준 물체가 같은 평면·카메라 정면 ±3–5%, 카드 ±6–10%, 다른 평면 ±10–15%. 플랫레이는 첫 번째 조건이라 가장 유리하다.

## 3. 효과가 있었던 설계 원칙

- **숫자는 기하와 규칙표에서만, LLM 문장은 숫자 가드를 통과해야 출력.** `src/lib/rules/numbers.ts`.
- **틀린 숫자보다 "재단사 측정"(측정 거부)이 낫다.** 두 클립에서 가드가 틀린 숫자 3개를 막았다.
- **사후 수정은 API 비용 0.** 결과 화면에서 "말한 뜻이 다르다면" 원탭으로 분류을 바꾸면 규칙만 다시 돈다. Rub-Off에서도 "이 조각은 소매가 아니라 몸판" 같은 수정은 재호출 없이.
- **묻는 건 나중에, 필요할 때만.** 사전 프로필 대신 사진에서 읽고 "맞습니까?"로 확인.
- **캐시는 입력의 SHA-256 키.** SAM·Spark 원문 전부 저장. 다시 돌릴 때 비용 0, 골든 런이 샘플 모드가 된다.
- **비용을 실행마다 찍는다.** 명령에 `--yes` 없으면 예상 비용만 출력.
- **컷 리스트를 미리 쓴다.** 밀리면 위에서부터 자른다. 절대 자르지 않는 것(얼굴 블러, ±, 재단 전 확인)도 적어 둔다.
- **촬영 안내는 실제 촬영 조건으로 검증한다.** "옆에서 찍어 달라"고 했는데 혼자 찍으면 위에서 찍혔다. Rub-Off는 바닥에 펴놓고 서서 내려찍는 게 자연스러우니 그 조건에서 시험한다(그림자, 기울기).

## 4. 도식화·패턴 표기 규칙 (FLAT-CONVENTIONS.md 요약)

- 선 굵기 3단계: 실루엣 가장 굵게, 솔기·스타일선 절반, 스티치 가장 가늘게 점선. 비율 1 : 0.5 : 0.3. 모든 도면에서 동일.
- 한쪽을 그려 대칭(mirror). 곡선은 중심선에 90°로 만난다.
- 앞·뒤는 같은 윤곽에서 나와 폭·길이가 맞아야 한다.
- 모든 패스를 닫는다. 음영·움직임 선 없음(공장은 솔기로 읽는다).
- 실제 비율, 디테일도 실제 치수(cm).
- 콜아웃은 번호 달아 실루엣 밖에, 흑백 인쇄에서도 읽히게(추가 원단은 해칭, 제거는 크로스해칭).
- 측정점 문자(A–D)와 측정표. 평면 폭은 "단면".
- 패턴의 길이 조정은 이중선 "lengthen or shorten here". Rub-Off 그레이딩 표시에 그대로 쓸 것.
- 참고 문헌: Points of Measure 튜토리얼, Garmentspec, 박주희 『패션 디자이너의 도식화』(교문사 2012), Szkutnicka *Technical Drawing for Fashion*, NIST CS 166-50(바지 측정점).
