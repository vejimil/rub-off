### 소유자 사진 4장 (10/31 오후): 티셔츠 앞·뒤(유니클로 UT, 니트), 집업 후드 앞·뒤

사진은 `.cache/owner/`에만 두고 커밋하지 않음(발·방이 보임). **네 장 모두 A4가 없어 cm 정확도는 아직 판단 불가.** 아래 cm 값은 "가슴단면 = 54/55 cm"라고 가정한 비례값이라 비율과 랜드마크 위치만 의미 있다.

| 발견 | 근거 | 조치 |
| --- | --- | --- |
| SAM 단어: `t-shirt` 0.99/0.85, `shirt`는 티셔츠 뒷면에서 0개. `hoodie` 0.92/0.73, `jacket`은 집업 후드에서 0개. `hood` 0.93/0.66 | `npm run explore`, 오버레이 `.cache/explore/` | 티셔츠 `t-shirt`, 후드 `hoodie` 사용 |
| SAM `sleeve`가 티셔츠 소매를 세트인 솔기선에서 정확히 자름(0.96, 0.97) → 어깨점이 소매 마스크 시작점으로 바로 나옴 | 같은 실행 | 어깨점 = 소매 마스크에서 옆목점에 가장 가까운 점 |
| 후드 앞면: 오른쪽 소매가 몸판 위로 접혀 있음. 기하(소매 마스크 중심이 몸판 안)와 **Muse Spark 확인("folded over the body") 둘 다 같은 판정** | `npm run photo -- .cache/owner/IMG_1218.JPG --garment=hoodie --ref=chest:55 --yes` | 접힌 쪽은 안 재고, 펴진 쪽을 밑단 중심선에 대칭(± 5% 추가) |
| 후드 뒷면: SAM `sleeve` 두 개 중 하나는 실제로 모자 | 같은 스크립트, IMG_1219 | `sleeve` 마스크가 `hood` 마스크와 30% 넘게 겹치면 소매에서 뺌 |
| 뒷면 두 장은 옷이 90° 돌아간 채 찍힘 → 처음엔 "목둘레를 찾지 못했습니다" | 같은 실행 | 모자(없으면 소매) 쪽을 위로 보고 90° 단위로 세움. 이후 두 장 모두 측정됨 |
| 티셔츠 앞면 왼쪽 소매, 후드 앞면 왼쪽 소맷부리가 사진 가장자리에 잘림. 잘린 소맷부리로 소매단면 5.1 cm 같은 틀린 값이 나옴 | 오버레이 확인 | 측정선 끝점이 사진 가장자리 4 px 안이면 그 값은 거부하고 이유를 씀 |
| 같은 티셔츠 앞·뒤의 (총장/가슴단면) 비율이 9% 다름(1.39 vs 1.27). 둘 다 Spark "주름 조금" | 비례값 비교 | 원인 후보: A4가 없어 기울기 보정 불가 + 주름. "주름 조금" ±를 1.5% → 4%로. **다음 촬영은 A4 필수** |
| 앞·뒤 합치기: 후드 앞면의 잘린 소맷부리를 뒷면의 늘어진 소매가 채워 후드 패턴 전체가 나옴. 목너비·팔통·어깨처짐은 두 장이 달라 충돌로 표시 | `npm run photo -- IMG_1218.JPG IMG_1219.JPG --garment=hoodie --ref=chest:55` | 값마다 ±가 작은 쪽을 쓰고, ± 밖으로 다르면 ±를 차이만큼 키움 |
| 노란 포장(다이소 철사 2P)은 크기를 알 수 없어 기준 물체로 못 씀 | 확대 확인 | A4 대신 줄자 값 하나를 기준으로 비례하는 대체 경로 추가(원근 보정 없음, ± 4% 이상) |

API 비용: SAM 약 22회 + Spark 확인 4회 ≈ $0.10.

## 아직 확인 못 한 것 (실제 사진·인쇄 필요)

- 셔츠·티셔츠 실제 사진에서 겨드랑이(오목점), 어깨점(SAM `sleeve` 마스크), 소매 끝(꺾임점) 찾기. 지금은 그린 도형 테스트만 통과
- SAM 단어 비교: `shirt`/`t-shirt`/`top`, `sleeve`, `skirt`, `bag`/`tote`, `handle`/`strap`, `fabric`/`cloth`
- 호모그래피를 옷 전체에 쓰는 것과 단순 px/cm의 정확도 비교(줄자 기준)
- PDF를 실제로 인쇄해 10 cm 사각형 ±2 mm 확인, 페이지 겹침 맞추기
- 옷 두께 때문에 윤곽이 커지는 계통 오차
