# 아키텍처 (구현 계획)

가정은 **[A]**. 첫 실행에서 확인한다.

## 공통 파이프라인 (사진 1장)

0. **입력.** JPEG/HEIC/PNG 업로드. 서버에서 sharp로 EXIF 회전 적용, 긴 변 2000 px로 리사이즈, 메타데이터 제거, SHA-256 키. **[A]** HEIC 디코딩은 sharp가 libheif 포함 빌드인지 확인.
1. **SAM 3.1 (이미지, 개념별 1회).** `paper`(A4), 옷 개념(`shirt` 또는 `t-shirt`, `pants`, `skirt`, `bag`: Spark가 옷 종류를 먼저 읽고 그에 맞는 단어 선택), 부위(`sleeve`, `collar`, `pocket`), 모드 3은 `fabric`. 병렬 호출. 결과 원문 캐시.
2. **스케일.** A4 마스크 → 변 직선 피팅 → 꼭짓점 → 비율 1.414 ± 6%, 가장자리 거부 → 호모그래피(네 꼭짓점 깨끗할 때) 또는 px/mm. 사진 평면 → cm 평면으로 모든 폴리곤 변환.
3. **윤곽과 측정점.** 옷 마스크 → 폴리곤(단순화 0.3 cm) → 소매 마스크로 몸판/소매 분리 → 측정점: 총장(뒷목점 또는 어깨선–밑단), 가슴단면(겨드랑이점 사이), 어깨너비, 소매길이, 밑단단면, 목너비. 각 값에 ±(스케일 ± + 윤곽 단순화 + 두께 보정 가정).
4. **Spark 구조 읽기 (구조화 출력, enum만).** 옷 종류, 소매 구조(세트인/래글런/없음), 원단(니트/우븐 추정), 여밈, 접힌 선 유무, 앞/뒤 사진인지. SAM 마스크를 색칠한 이미지를 함께 보여 "이 색 조각이 무엇인지" 고르게 한다. 숫자 없음.
5. **확인 화면.** "셔츠, 세트인 소매, 우븐으로 읽었습니다. 맞습니까?" 원탭 수정, API 재호출 없음.

## 모드 1: 패턴

- **대칭화.** 몸판 폴리곤을 중심선(어깨점 중점–밑단 중점)으로 좌우 평균. 좌우 차이가 3% 넘으면 경고(옷이 비뚤게 놓임).
- **조각 만들기.**
  - 앞 몸판: 대칭화된 윤곽 + 앞 목선. 뒤 사진이 있으면 뒤 몸판 따로, 없으면 같은 윤곽에 뒷목 깊이 규칙(표).
  - 소매: 펴놓은 소매는 윗선이 접힌 선 → 그 선으로 대칭시켜 한 장. 소매산 곡선 길이 = 앞·뒤 암홀 길이 + 이즈(우븐 1–1.5 cm, 니트 0) 되도록 소매산 높이를 수치 탐색으로 맞춘다. **[A]** 플랫레이에서 암홀 곡선이 충분히 보이는지.
  - 칼라·커프스·안단: 길이는 측정, 폭은 측정 또는 규칙표. 직사각형.
- **시접.** 폴리곤 바깥 오프셋(라이브러리: `polygon-clipping` 또는 `clipper-lib`; 없으면 간단 오프셋 직접). 규칙표: 옆선·어깨 1 cm, 암홀 1 cm, 밑단 2.5 cm, 목선 0.7 cm, 니트 0.7 cm. 소유자가 확정.
- **표기.** 식서 방향(세로 화살표), 골선(앞 중심 "fold"), 너치(어깨점, 겨드랑이점, 소매산 중앙, 앞/뒤 구분 1·2개), 조각 이름·장수·사이즈·날짜, "재단 전 확인", 10 cm 검증 사각형. FLAT-CONVENTIONS 선 굵기.
- **그레이딩.** 규칙표 `grading.ts`: 사이즈 1단계당 가슴단면 +2 cm(=둘레 +4), 총장 +1.5, 어깨 +1, 소매 +1 등 **[A] 소유자 작성**. 분배 지점(옆선·어깨·중심)별 이동량. 지정 치수 입력도 같은 표로 역산.
- **출력.** SVG(cm 단위 viewBox) → `pdf-lib`로 1:1 A4 타일(겹침 1 cm, 모서리 맞춤 표시, 페이지 번호 행·열), 전체 축소 안내도 1장. 브라우저 인쇄 "실제 크기" 안내.
- **검증.** 인쇄 후 10 cm 사각형 자로 확인. 원본 줄자 치수와 패턴 치수(시접 제외) 차이를 표로.

## 모드 2: 사이즈 결정

- 내 옷: 공통 파이프라인의 측정점.
- 실측표: 스크린샷 → Spark 구조화 출력 `{unit: cm|inch, basis: half|circumference|unknown, sizes[{label, chest, length, shoulder, sleeve, hem, waist, ...}]}`. 숫자는 그대로 옮기게 하고, 되돌려 보여 주며 "표와 같습니까?" 확인(Spark OCR 오류 대비). `basis: unknown`이면 사용자에게 묻는다.
- 비교: 측정점별 차이 = 표 − 내 옷. 허용 범위 규칙표: 우븐 가슴 −1~+2, 니트 −2~+2, 총장 ±2, 어깨 ±1, 소매 ±1.5 **[A]**. 원하는 핏(그대로/여유/타이트)으로 범위 이동. 점수 = 범위 안 항목 수, 동률이면 가슴 우선. 출력: 추천 사이즈, 항목별 ✓/△/✗와 cm, 걸리는 항목 문장(숫자 가드 통과).
- 샘플: 레포에 자작 실측표 이미지 1장(실제 쇼핑몰 캡처 금지).

## 모드 3: 재단 배치

- 원단: `fabric` 마스크 → cm 폴리곤(여러 조각 가능). 식서 방향은 사용자가 화살표로 지정(기본: 사진 세로).
- 조각: 모드 1 결과 또는 SVG 업로드.
- 배치: 1 cm 격자 래스터, 조각을 큰 것부터 bottom-left-fill, 허용 회전 0°/180°(식서), 옵션 90°. 조각 사이 여유 0.5 cm. 못 들어가면 가장 작은 부족량(가로/세로 cm)을 보고.
- 출력: 원단 사진 위에 조각 윤곽 오버레이 + cm 좌표표.

## 모드 1 미리보기 (있으면)

Muse Image로 몸판 영역을 "이 원단 무늬로" 편집 → SAM 몸판 마스크로만 원본에 합성 → Spark에게 마스크 밖이 바뀌었는지 확인.

## 숫자 가드

문장 템플릿은 코드가 채운다. Spark가 쓴 설명문이 있으면 그 안의 모든 숫자가 계산값 집합(±반올림)에 있어야 하고, 아니면 그 문장을 버린다. (`numbers.ts` 이식.)

## 호스팅

- 사진만 다루고 ffmpeg가 없으므로 **Vercel**(Node 런타임 라우트, `@meta-sam/parser`)로 충분 **[A]** 업로드 4.5 MB 제한 → 클라이언트에서 2000 px로 리사이즈한 뒤 전송.
- 샘플 모드: 골든 런 JSON + 이미지 정적 번들, API 0회.
- 라이브 모드: `ALLOW_LIVE_RUNS=1`일 때만, 방문자별 5회/일, 전역 100회/일 **[A]**, 키는 서버만.

## 리스크와 대비

| 리스크 | 대비 |
| --- | --- |
| SAM이 소매·칼라를 못 나눔 | Spark 0–1000 좌표(겨드랑이점)를 SAM 포인트 프롬프트로, 그래도 안 되면 사용자가 겨드랑이점 두 개 탭 |
| 옷 두께로 윤곽이 커짐 | 첫 촬영 때 줄자 비교로 보정 상수, ±에 반영 |
| 소매산 피팅 실패 | 소매산 높이를 규칙표 기본값(암홀 깊이의 0.6)으로 두고 "확인" 표시 |
| PDF 1:1 인쇄 축소 | 10 cm 사각형 + 인쇄 설정 안내 |
| Spark 표 OCR 오류 | 되돌려 보여 주고 확인, 셀 단위 수정 |
| 시간 부족 | 컷 리스트 순서: Muse Image 미리보기 → 모드 3 → 그레이딩 → 뒤 사진 → 모드 2. **절대 자르지 않는 것:** 스케일 가드, ±, "재단 전 확인", 10 cm 사각형 |
